Доступность (a11y) в Canvas-мультиках

Введение

Canvas — это «чёрный ящик» для вспомогательных технологий. Screen reader видит только тег <canvas> и, если ему не предоставить альтернативу, понятия не имеет, что на экране происходит. В нашем проекте «Пирожки с нуля» анимированный мультик рассказывает историю приготовления пирожков: шеф-повар крутит тесто, вода кипит, пар поднимается. Для зрячего пользователя всё очевидно. Но как быть для слабовидящих, людей с нарушениями цветового зрения или тех, кто пользуется клавиатурой вместо мыши?

В этой статье разберём, как сделать Canvas-мультик доступным, не теряя визуальное качество.

1. Проблема: Canvas = чёрный ящик

Элемент <canvas> по умолчанию не имеет семантического значения. Скринридер (NVDA, VoiceOver, JAWS) прочитает только то, что находится между тегами <canvas>...</canvas>. Если там пусто — пользователь услышит «Graphic» или ничего.

Причины:
— Canvas рендерит пиксели, а не DOM-элементы. Нет document node tree.
— Нет built-in поддержки ARIA для содержимого canvas.
— Динамический контент (анимация) не индексируется по умолчанию.

В проекте «Пирожки» у нас десятки сцен: интро, варка теста, формовка, выпечка, финал. Каждая сцена — это визуальная история. Для доступности её нужно перевести на «человеческий язык».

2. ARIA-описания и текстовые альтернативы

Первый и самый важный шаг — предоставить описание:

<canvas id="stage" aria-label="Анимированный мультик: приготовление пирожков от теста до готового изделия">
  <p>Этот мультик показывает процесс приготовления пирожков: замешивание теста, формовка, выпечка в духовке. Нажмите Enter для начала.</p>
</canvas>

Тег <canvas> с fallback-контентом (внутри тегов) читается скринридером, если canvas недоступен. Однако для полностью доступного опыта нужно больше.

Динамические ARIA live-регионы:

<div id="scene-description" aria-live="polite" class="sr-only"></div>

В JavaScript при смене сцены обновляем описание:

function changeScene(sceneId) {
  const desc = document.getElementById('scene-description');
  desc.textContent = SCENES[sceneId].description;
  // SCENES['boil'].description = 'Шеф ставит миску с водой на плиту. Вода начинает кипеть.';
}

Это позволит скринридеру объявить, что происходит, без необходимости «видеть» canvas.

3. Клавиатурная навигация

Многие пользователи не используют мышь. Canvas-интерактив (кнопки, контроль воспроизведения) должен быть доступен через клавишу Tab и Enter.

В нашем проекте:
— Кнопка «Смотреть» на экране интро получает tabindex="0".
— Управление воспроизведением: пробел — паusa/play, стрелки вперёд/назад — перемотка по сценам.
— Replay-панель в финале: три карточки с пресетами доступны через Tab.

Пример обработки клавиатуры:

canvas.setAttribute('tabindex', '0');
canvas.addEventListener('keydown', (e) => {
  if (e.key === ' ' || e.key === 'Enter') togglePlay();
  if (e.key === 'ArrowRight') nextScene();
  if (e.key === 'ArrowLeft') prevScene();
});

4. Контрастность и цвет

По стандартам WCAG 2.1 текст должен иметь контрастность не менее 4.5:1 к фону, а крупный текст — не менее 3:1. В Canvas мы рисуем текст вручную, поэтому должны следить за контрастностью самостоятельно.

Проблема в «Пирожках»: белый текст на светлом фоне миски, жёлтые субтитры на золотистом фоне теста. Решение — добавлять тёмную обводку или тень к тексту:

ctx.shadowColor = 'rgba(0,0,0,0.8)';
ctx.shadowBlur = 4;
ctx.fillStyle = '#FFFFFF';
ctx.font = 'bold 20px Arial';
ctx.fillText(sub.title, x, y);

Также полезно oferecer 고대비 모드 (high contrast mode) — в CSS:

@media (prefers-contrast: high) {
  .subtitle { text-shadow: 2px 2px 4px #000; font-weight: bold; }
}

5. Color-blind friendly палитры

Около 8% мужчин и 0.5% женщин имеют нарушения цветового зрения (daltonism). Типичные проблемы:
— Красный-зелёный: не различают спелый помидор и лист.
— Синий-жёлтый: путают голубой и серый.

В мультике «Пирожки»有很多 цветовых сигналов: красный = «горячо» (духовка), зелёный = «готово» (галочка в финале), жёлтый = «масло/сырое тесто».

Решения:
— Не полагаться только на цвет. Добавлять иконки, текстовые метки, паттерны.
— Использовать безопасные палитры (ColorBrewer, Viridis).
— Тестировать через симуляторы дальтонизма (Chrome DevTools → Rendering → Emulate vision deficiencies).

Пример: в финальном экране ингредиенты отмечены галочками ✅, а не просто зелёным фоном. Тайминг-блоки используют не только цвет, но и текстовые метки («3 мин», «10 мин»).

6. Fallback-контент

Помимо ARIA-описаний, полезно ofrecer полную текстовую версию мультика:

<details>
  <summary>Текстовая версия мультика</summary>
  <ol>
    <li>Шеф-повар приветствует зрителей.</li>
    <li>Замешивание теста: мука, вода, дрожжи, масло.</li>
    <li>Формовка пирожков.</li>
    <li>Выпечка в духовке при 180°C, 20 минут.</li>
    <li>Готовые пирожки — Bon appetit!</li>
  </ol>
</details>

Этот fallback виден всем пользователям (через <details> можно раскрыть) и особенно полезен для скринридеров.

Заключение

Доступность Canvas-мультика — это не компромисс, а расширение аудитории. ARIA-описания, клавиатурная навигация, контрастность, color-friendly палитры и fallback-контент — всё это делает наш «Пирожок с нуля» доступным для каждого зрителя. Инвестиции в a11y окупаются лояльностью аудитории и соответствием стандартам.
