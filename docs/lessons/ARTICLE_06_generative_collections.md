# PolyArt Статья 06: Генеративные коллекции и NFT

## Проблема

Для генеративных коллекций (NFT, стикерпаки, карточные игры) нужны
тысячи уникальных изображений одного стиля.

## Подход

Один алгоритм + переменные параметры (seed, палитра, композиция) =
бесконечная серия в едином стиле.

## Пример: коллекция «Закаты»

```python
import numpy as np
from polyart_painter import PainterCanvas

PALETTES = [
    ("#f0c020", "#d94a2a"),  # огненный
    ("#f0e0c0", "#c8a040"),  # медовый
    ("#d9c8a8", "#8a5a2a"),  # песочный
    ("#e8b090", "#d94a6e"),  # розовый
]

def sunset_nft(seed):
    c1, c2 = PALETTES[seed % len(PALETTES)]
    t = np.linspace(-6, 6, 200)
    c = PainterCanvas(name=f"Закат #{seed}", xlim=(-6, 6), ylim=(-6, 6))
    c.wet_on_wet(t, 3, c1=c1, c2=c2, width=2.4)
    c.brush(size="flat", paint=c2, load=0.8, seed=seed)
    c.stroke(t, -2 + 0.4*np.sin(t*0.7 + seed), pressure=0.6)
    return c

for seed in range(100):
    sunset_nft(seed).render(f"nft/sunset_{seed:03d}.png", dpi=200)
```

## Метаданные

Для каждой картинки храните JSON: seed, палитру, параметры кисти.
Полиарт сохраняет это в `.polyart`-файле.

## Плюсы

- **Единый стиль**: один алгоритм.
- **Уникальность**: seed меняет фактуру.
- **Воспроизводимость**: тот же seed — та же картина.
- **Справедливость**: алгоритм, а не «выбор автора».

## Итог

Полиарт подходит для генеративных коллекций: быстрая генерация,
воспроизводимость, метаданные и стилистическое единство.
