# PolyArt Статья 07: Мобильные игры и генерация арта на лету

## Проблема

В мобильных играх нельзя хранить тысячи больших текстур. Нужен арт,
который генерируется в рантайме и весит мало.

## Решение

Полиарт хранит не картинку, а формулу. Мазки масляной кисти строятся
из кривых и параметров — это килобайты данных вместо мегабайтов PNG.

## Генерация по запросу

```python
from polyart_painter import PainterCanvas
import numpy as np

def level_background(theme, seed):
    c = PainterCanvas(name=theme, xlim=(-6, 6), ylim=(-6, 6))
    t = np.linspace(-6, 6, 160)
    if theme == "dawn":
        c1, c2 = "#f0c020", "#d94a2a"
    elif theme == "night":
        c1, c2 = "#2a4a8a", "#1a2a5a"
    else:
        c1, c2 = "#c8a040", "#8a6a3a"
    c.wet_on_wet(t, 3, c1=c1, c2=c2, width=2.2)
    c.brush(size="flat", paint=c2, load=0.8, seed=seed)
    c.stroke(t, -2 + 0.3*np.sin(t), pressure=0.6)
    return c

# три разных уровня — три темы
level_background("dawn", 1).render("lv1.png", dpi=100)
level_background("night", 2).render("lv2.png", dpi=100)
level_background("forest", 3).render("lv3.png", dpi=100)
```

## Плюсы для мобильных

- **Вес**: код вместо текстур.
- **Память**: фон строится за миллисекунды.
- **Настройка**: тема и seed из конфига уровня.
- **Уникальность**: каждый уровень неповторим.

## Тонкость

Для реального рантайма используйте numpy-массивы и кэшируйте
результат при необходимости. Для превью на этапе разработки —
рендер в PNG.

## Итог

Полиарт — это «живой» формат арта для мобильных игр: мало весит,
генерируется на лету, бесконечно варьируется.
