CANVAS vs SVG vs WebGL: ПОЧЕМУ CANVAS 2D ДЛЯ МУЛЬТИКОВ
═══════════════════════════════════════════════════════

Введение
────────

Выбор рендеринг-технологии — одно из первых архитектурных решений при создании анимированного мультика на веб-платформе. Три основных кандидата: Canvas 2D, SVG и WebGL. Каждый имеет свои сильные и слабые стороны. Проект «Пирожки с нуля» выбрал Canvas 2D — и выбор этот не случаен. Разберём, почему именно Canvas 2D оптимален для анимированных историй.


Canvas: растровый, быстрый для пиксельных операций
──────────────────────────────────────────────────

Canvas — это растровая поверхность. Каждый пиксель управляется напрямую через ArrayBuffer. Это даёт:

Преимущества:
- Полный контроль над каждым пикселем
- Быстрая отрисовка сложных сцен (тысячи элементов за кадр)
- Прямой доступ к пиксельным данным (getImageData/putImageData)
- Нативная поддержка градиентов, теней, composite операций
- Лёгкая интеграция с таймером анимации (requestAnimationFrame)

Ограничения:
- Масштабирование: при увеличении — пикселизация
- Accessibility: растровое изображение не доступно скринридерам
- Перерисовка: каждый кадр рисуется заново (но это и преимущество для анимации)

Canvas идеален для:
- Пиксельных операций (фигуры, градиенты, текстуры)
- Анимации с высокой частотой кадров (60 FPS)
- Интерактивных сцен с динамическим контентом

В проекте «Пирожки с нуля» Canvas используется для:
- Отрисовки сцен кухни (стол, посуда, ингредиенты)
- Анимации персонажа (руки, движение)
- Mood-системы (динамические фоны)
- Эффектов (пар, крошки, блики)


SVG: векторный, хорош для иконок
─────────────────────────────────

SVG — Scalable Vector Graphics. Векторный формат, основанный на XML-описании фигур.

Преимущества:
- Масштабирование без потери качества
- Семантическая структура (DOM-элементы)
- Доступность (скринридеры понимают SVG)
- CSS-стилизация и анимация
- Хорош для иконок, диаграмм, простых фигур

Ограничения:
- Медленная отрисовка сложных сцен (ousands of paths)
- DOM-перегрузка: каждый элемент — DOM-узел
- Сложная анимация: требует SMIL или JS-управления
- Нет пиксельного контроля (фильтры ограничены)

SVG хорош для:
- Иконок и логотипов
- Интерфейсных элементов (кнопки, меню)
- Статичных или малоизменяющихся изображений
- Доступного контента

В контексте мультика SVG не подходит, потому что:
- Анимация 50+ элементов одновременно → лаги
- Нет прямого доступа к пикселям
- Масштабирование路径ограничено для сложных текстур


WebGL: 3D, избыточно для 2D
───────────────────────────

WebGL — это 3D-рендеринг через OpenGL ES в браузере. Полная трёхмерная графика с шейдерами.

Преимущества:
- 3D-графика: модели, текстурирование, освещение
- GPU-ускорение: аппаратная отрисовка
- Шейдеры: произвольные визуальные эффекты
- Масштабирование: от 4K до мобильных экранов

Ограничения:
- Сложность: шейдеры на GLSL, матрицы трансформаций
- Overkill для 2D-анимации: 3D-движок для плоских историй
- Производительность на слабых устройствах: GPU-зависимость
- Accessibility: полное отсутствие семантики

WebGL подходит для:
- 3D-игр и визуализаций
- Сложных шейдерных эффектов
- Визуализации данных в 3D
- VR/AR-контента

Для 2D-мультика WebGL — это как стрелять из пушки по воробьям. Технически возможно, но зачем, если Canvas 2D делает то же самое проще и быстрее?


Почему Canvas 2D: простота, скорость, контроль пикселей
──────────────────────────────────────────────────────

Canvas 2D — золотая середина для анимированных историй:

Простота:
- API понятен с первого дня
- Нет компилятора шейдеров
- Нет управления DOM-деревом
- Прямой вызов методов: fillRect, arc, drawImage

Скорость:
- Оптимизирован для 2D-операций
- Hardware acceleration через Canvas 2D context
- Меньше overhead, чем SVG (нет DOM)
- Достаточно для 60 FPS в сложных сценах

Контроль пикселей:
- getImageData() — чтение пикселей
- putImageData() — запись пикселей
- Текстуры, градиенты, тени — всё нативно
- Alpha-канал, composite операции, clipping

Для проекта «Пирожки с нуля» Canvas 2D — идеальный выбор:
- Нужна анимация еды → пиксельный контроль важен
- Нужна параллакс-система → быстрая отрисовка слоёв
- Нужна mood-система → градиенты и динамические фоны
- Нужна доступность → можно добавить HTML-оверлей


Ограничения: масштабирование, accessibility
───────────────────────────────────────────

Canvas 2D не идеален. Основные ограничения:

Масштабирование:
- Растровое изображение → пикселизация при zoom
- Решение: рендеринг при devicePixelRatio
- Решение: перерисовка при изменении размера

function resizeCanvas() {
  const dpr = window.devicePixelRatio || 1;
  canvas.width = W * dpr;
  canvas.height = H * dpr;
  canvas.style.width = W + 'px';
  canvas.style.height = H + 'px';
  ctx.scale(dpr, dpr);
}

Accessibility:
- Canvas не имеет семантической структуры
- Решение: дублирование контента через HTML
- Решение: ARIA-описания для скринридеров
- Решение: текстовые альтернативы (субтитры)

В проекте «Пирожки с нуля» accessibility решается через:
- Субтитры на Canvas (текстовый слой)
- HTML-кнопки replay поверх Canvas
- ARIA-labels для интерактивных элементов


Заключение
──────────

Выбор Canvas 2D для проекта «Пирожки с нуля» — осознанное решение, основанное на балансе простоты, производительности и контроля. SVG хорош для иконок, WebGL — для 3D, но Canvas 2D даёт именно то, что нужно для анимированного мультика: быструю отрисовку, полный контроль над пикселями и простой API. Ограничения масштабирования и accessibility решаются дополнительными техниками, не перегружая основную архитектуру.
