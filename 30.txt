ЧЕКЛИСТ КАЧЕСТВА: ЧТО ПРОВЕРИТЬ ПЕРЕД РЕЛИЗОМ МУЛЬТИКА
═════════════════════════════════════════════════════════

Введение
────────

Релиз мультфильма — это не «просто запустить». Это многоуровневая проверка качества, которая включает визуальные тесты, проверку производительности, тестирование на разных устройствах и проверку доступности. Проект «Пирожки с нуля» прошёл через этот чеклист, и каждый пункт — это потенциальный баг, который мог бы испортить впечатление зрителя. Составим полный чеклист перед релизом.


Список проверок: визуальные баги, тайминг субтитров, работа всех сцен, камеры, replay
──────────────────────────────────────────────────────────────────────────────────────

Визуальные баги:
- [ ] Нет «mergause» (артефактов наложения) между слоями
- [ ] Градиенты отрисовываются без полосатости (banding)
- [ ] Текст читается на любом фоне (контраст > 4.5:1)
- [ ] Анимация плавная, без рывков (60 FPS на desktop)
- [ ] Нет « мерцания » при смене эпизодов
- [ ] Цвета соответствуют mood-системе

Тайминг субтитров:
- [ ] Субтитры появляются вовремя (±200мс)
- [ ] Субтитры исчезают до следующей фразы
- [ ] Длительность чтения: минимум 1.5 сек на строку
- [ ] Максимум 2 строки на экран одновременно
- [ ] Шрифт читается на мобильных (минимум 14px)

Работа всех сцен:
- [ ] ПРОЛОГ: загрузка, начальная анимация
- [ ] ПРОБУЖДЕНИЕ: оживление кухни
- [ ] СМЕШЕНИЕ: процесс замешивания
- [ ] ФОРМОВКА: лепка пирожков
- [ ] ВЫПЕЧКА: Maillard reaction анимация
- [ ] ФИНАЛ: результат, replay-кнопки

Камеры (replay-система):
- [ ] Closeup: zoom 1.8x работает корректно
- [ ] Wide: zoom 0.7x работает корректно
- [ ] Drama: драматическое движение камеры
- [ ] Плавный переход между пресетами
- [ ] Камера не «уезжает» за пределы сцены

Replay:
- [ ] Кнопки replay появляются в финале
- [ ] Каждая кнопка запускает правильный пресет
- [ ] Replay корректно перезапускает сцену
- [ ] Прогресс-бар сбрасывается при replay
- [ ] Настройки сохраняются между replay


Тестирование на разных размерах экрана
──────────────────────────────────────

Desktop (1920x1080):
- [ ] Canvas заполняет экран без искажений
- [ ] Кнопки replay доступны и кликабельны
- [ ] Прогресс-бар виден, но не перекрывает контент
- [ ] FPS: стабильные 60

Desktop (1366x768):
- [ ] Canvas масштабируется пропорционально
- [ ] Кнопки replay не выходят за пределы экрана
- [ ] Субтитры читаемы

Tablet (768x1024):
- [ ] Canvas адаптируется под портретную ориентацию
- [ ] Touch-кнопки достаточного размера (48x48px)
- [ ] Параллакс работает плавно

Mobile (375x667):
- [ ] Canvas масштабируется без потери контента
- [ ] Кнопки replay доступны для тапа
- [ ] Субтитры не обрезаются
- [ ] Прогресс-бар тонкий, но видимый

Ультра-широкий (3440x1440):
- [ ] Canvas центрируется, не растягивается
- [ ] Боковые полосы (pillarbox) эстетичны


Производительность: FPS
──────────────────────

Тестирование производительности:

Desktop Chrome:
- [ ] FPS: 60 стабильно
- [ ] Memory: < 100MB
- [ ] CPU: < 30% при воспроизведении

Desktop Firefox:
- [ ] FPS: 60 стабильно
- [ ] Memory: < 120MB
- [ ] CPU: < 35%

Mobile Safari (iOS):
- [ ] FPS: 30 стабильно (уреженный режим)
- [ ] Memory: < 80MB
- [ ] Battery drain: < 10% за 5 минут

Mobile Chrome (Android):
- [ ] FPS: 30-60 стабильно
- [ ] Memory: < 100MB
- [ ] Thermal: нет перегрева

Инструменты тестирования:
- Chrome DevTools → Performance tab
- Firefox DevTools → Performance tab
- Safari Web Inspector → Timeline
- Lighthouse → Performance score > 90

Оптимизации для производительности:
- canvas.width/height = devicePixelRatio * CSS size
- requestAnimationFrame вместо setInterval
- Минимум GC (сборщика мусора) в игровом цикле
- Texture caching для повторяющихся элементов


Доступность: Alt-тексты, контраст
────────────────────────────────

Доступность (accessibility) — критически важный аспект:

Альтернативный текст:
- [ ] Canvas имеет aria-label с описанием сцены
- [ ] Каждая сцена имеет текстовое описание
- [ ] Субтитры доступны как отдельный текстовый слой

Контраст:
- [ ] Текст субтитров: контраст > 4.5:1 к фону
- [ ] Кнопки: контраст > 3:1 к фону
- [ ] Прогресс-бар: контраст > 3:1 к фону

Навигация:
- [ ] Tab между кнопками replay
- [ ] Enter/Space для активации кнопок
- [ ] Escape для паузы

Скринридеры:
- [ ] Canvas имеет role="img"
- [ ] aria-describedby ссылается на описание сцены
- [ ] Динамические изменения announcements

Реализация в проекте:

<canvas
  role="img"
  aria-label="Анимированный мультфильм о приготовлении пирожков"
  aria-describedby="scene-description"
></canvas>
<div id="scene-description" class="sr-only">
  Сцена 1: Персонаж стоит на кухне, начинает готовить тесто
</div>

Chrome (последние 3 версии):

- [ ] Canvas 2D API: полная поддержка
- [ ] Аудио: OK (если добавлено)
- [ ] Touch: OK

Firefox (последние 3 версии):
- [ ] Воспроизведение: OK
- [ ] Canvas 2D API: полная поддержка
- [ ] Аудио: OK
- [ ] Touch: OK

Safari (последние 3 версии):
- [ ] Воспроизведение: OK
- [ ] Canvas 2D API: полная поддержка
- [ ] Аудио: requires user interaction для автозапуска
- [ ] Touch: OK

Edge (последние 3 версии):
- [ ] Воспроизведение: OK (Chromium-based)
- [ ] Canvas 2D API: полная поддержка
- [ ] Аудио: OK
- [ ] Touch: OK

Особенности Safari:
- Автозапуск аудио заблокирован → нужна начальная кнопка
- requestAnimationFrame может работать по-другому в фоновых вкладках
- iOS Safari: canvas может быть ограничен по размеру

Особенности Firefox:
- Медленнее Chrome в 2D Canvas операциях (на ~10-15%)
- DevTools Performance может показывать другие метрики


Заключение
──────────

Чеклист качества — это не формальность, а необходимость. Проект «Пирожки с нуля» прошёл через все пункты этого чеклиста, и каждый найденный баг был исправлен до релиза. Визуальные тесты, проверка производительности, тестирование на мобильных устройствах и доступность — всё это составляющие профессионального продукта. Перед релизом каждого мультфильма стоит пройти этот чеклист полностью. Качество — это не случайность, это результат системного подхода.
