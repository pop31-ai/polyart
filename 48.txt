МАСШТАБИРОВАНИЕ: ОТ ОДНОГО МУЛЬТИКА К ПЛАТФОРМЕ

Введение

Проект «Пирожки с нуля» — это один мультик в одном HTML-файле. Но за каждой его частью скрывается потенциал масштабирования: движок можно переиспользовать, шаблоны сцен — адаптировать, библиотеку персонажей — расширять. Вопрос в том, как перейти от одного мультика к платформе, которая позволяет создавать десятки анимаций с минимальными усилиями.

В этой статье мы разберём стратегии масштабирования: повторное использование движка, шаблоны сцен, конфигурируемые параметры и автоматическая генерация контента.

1. Повторное использование движка

Движок «Пирожков с нуля» — это render loop, таймлайн и система частиц. Он не привязан к конкретному сюжету. Чтобы создать новый мультик, достаточно написать новые функции сцен и обновить массив SCENES. Движок остаётся прежним.

Для масштабирования движок нужно вынести в отдельный модуль: engine.js. Туда войдут requestAnimationFrame-цикл, обработка времени, система частиц и utility-функции (drawBowl, drawChef). Новый муль틱 подключает engine.js и добавляет свои сцены. Это стандартный подход: ядро + плагины.

В «Пирожках с нуля» такой подход уже применяется неявно: сцены изолированы, движок не знает о конкретных функциях. Явное выделение engine.js — логический следующий шаг.

2. Шаблоны сцен

Многие сцены в анимации следуют типичным паттернам: «введение персонажа», «демонстрация процесса», «кульминация», «заключение». Каждый паттерн можно оформить как шаблон с параметрами.

Шаблон «процесс»:
  SC_process(ctx, W, H, t, {
    subject: 'dough',     // объект
    action: 'kneading',   // действие
    duration: 8,          // длительность
    particles: 'flour',   // тип частиц
    palette: { ... }      // цвета
  })

Такой шаблон описывает通用ную логику: объект в центре, действие выполняется циклически, частицы создают атмосферу. Конкретные данные (что за объект, какое действие) передаются как параметры. Это позволяет создавать новые сцены без написания нового кода.

3. Библиотека персонажей

Шеф-повар из «Пирожков с нуля» описан спецификацией. Если мы хотим создавать мультики с другими персонажами, нужна библиотека спецификаций. Формат: JSON-файл с параметрами персонажа (пропорции, цвета, позы, анимации).

Пример:
  {
    "name": "chef",
    "proportions": { "head": 18, "body": 40, "arms": 35 },
    "colors": { "skin": "#FFD5B0", "hair": "#8B0000" },
    "poses": { "standing": [...], "waving": [...] },
    "animations": { "jump": [...], "nod": [...] }
  }

Функция drawChef загружает спецификацию и рисует персонажа по параметрам. Новый персонаж — новый JSON-файл, без изменения кода отрисовки.

4. Конфигурируемые параметры

Мультик должен быть настраиваемым без перекомпиляции. Ключевые параметры: длительность (общая и каждой сцены), количество сцен, палитры, персонажи, озвучка. Эти параметры выносятся в конфигурационный файл (config.json).

Пример конфига:
  {
    "title": "Пирожки с нуля",
    "duration": 72,
    "scenes": ["intro", "knead", "filling", "shape", "bake", "climax", "serve", "taste"],
    "characters": ["chef", "narrator"],
    "palette": { "bg": "#FFF8E7", "accent": "#FF6347" }
  }

Движок читает конфиг и автоматически настраивает таймлайн, загружает нужные сцены и персонажей.

5. Автоматическая генерация HTML из JSON

Кульминация масштабирования — автоматическая генерация. На входе: JSON с конфигурацией, спецификациями персонажей, сценарием и палитрами. На выходе: готовый HTML-файл с мультиком.

Процесс: парсинг JSON → генерация кода сцен (по шаблонам) → вставка спецификаций персонажей → добавление таймлайна субтитров → сборка в один HTML. Это можно реализовать как Node.js-скрипт или онлайн-конструктор.

В «Пирожках с нуля» этот подход ещё не реализован, но архитектура проекта (модульные сцены, изолированные функции, JSON-спецификации) делает его реализуемой без переписывания кода.

6. CI/CD для контента

Если мультики генерируются автоматически, их можно версионировать и публиковать через CI/CD. Git-репозиторий хранит JSON-конфиги, скрипт генерации создаёт HTML, GitHub Actions публикует на GitHub Pages. Изменение сценария → коммит → автоматическая пересборка → обновлённый мультик.

Это превращает создание контента в процесс, аналогичный разработке ПО: версионирование, код-ревью, автоматическое тестирование.

Заключение

Масштабирование от одного мультика к платформе — это последовательное выделение общих компонентов: движок, шаблоны, спецификации, конфиги. «Пирожки с нуля» уже имеют модульную архитектуру, которая позволяет это сделать. Следующий шаг — явная формализация: engine.js, templates/, characters/, config.json, генератор. Это превратит один мультик в фабрику анимации.
